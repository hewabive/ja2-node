# Deliberate deviations from the original

Every place where ja2-node knowingly and permanently differs from JA2 Stracciatella with default settings (the
behaviour reference, `01` D1). Add an entry to its section: the original's behaviour (with `file:line` where it helps),
what ja2-node does, and why. Behaviour that is not ported yet is not a deviation: it is an entry of `gaps.md`. Other
docs cite entries by their *Area* name (`deviations "Area"`); names are unique across both files.

Most entries replace wall clocks, frames, sound lengths, message boxes, cursors and screens with game time, commands
and decision prompts, move cosmetic draws off the gameplay generator, keep saves free of side effects, or avoid the
original's undefined behaviour, hangs and softlocks.

## 2. Timing and clocks

Wall clocks, frames and sound lengths replaced by game time on 5 ms ticks (D3, `04` §3).

| Area | Original | ja2-node | Why |
|---|---|---|---|
| Timing | Wall-clock timers that never catch up; frame-rate dependent bullets, burst cadence and real-time AI slice | Fixed 5 ms ticks; bullets advance N tiles per tick; a fixed number of real-time AI soldiers per pass | Outcomes independent of FPS and CPU (`04` §3) |
| Speech | A quote lasts its audio (speech on) or 60 ms per character, then 300 ms with the mouth closed | For every viewer the longer of the two (the rule pack's voice length, 12 ticks per character + 1; `24` §7.6), then 60 ticks mouth closed; never waits for the speaker's battle sound. The viewer that finished first (voice, or text with speech off) leaves only the 60 ticks (`skipLine {talkEnded}`, an input); a viewer with the other speech option trails by the difference | One simulation serves every viewer and must not depend on audio (`04` §3, `29` §14, `24` §10.2) |
| Skipping every line | No such setting | `speech: skip` (`newSession`, `setSpeech`): every line ends on the tick after it is said, as if Backspace were pressed at once; its quote event carries `skipped` and no viewer shows it; a logged session setting, never saved | Agents playing with nobody listening (`29` §14) |
| Watchdogs | 15 s AI deadlock breaker, 25 s UI busy breaker | Not ported | A hang is a bug and must fail tests |
| Frame timers | `TIMECOUNTERDONE` against the wall clock, polled every 5 ms | Absolute game-ms deadlines checked on 5 ms ticks, same reset points | Same cadence without wall-clock jitter (`01` §3.5) |
| Enemy sighted on their turn | 3 s wall-clock pause (`GameScreen.cc`) | 3000 game ms; the simulation is not idle meanwhile, so time runs through our interrupt until it ends (`10` §6.9) | Game time |
| Bullet flight | `MoveBullet` runs once per frame, gated by a 2–3 ms wall clock, so flight time and burst overlap follow the frame rate | One tile per 5 ms tick at the start of the tick, the first inside `FireWeapon`; knives every 30 ms | Outcomes independent of FPS (`11` §3.3) |
| Game events | Fire events run in the frame's event pump | Same queue order, drained after each tick's soldier pass | No frame loop (`11` §1.2) |
| Our merc's death | The barrier is released after the portrait and skull animation (12 × 160 ms wall clock) | A fixed 1920 game ms after opcode 440 | UI timing has no game clock |
| Blood and smell decay period | `DecayBloodAndSmells` runs after more than 100 game seconds, or 5 real seconds of game time under compression (`5 · 300/1800/3600` s) | Always after more than 100 game seconds | Only changes how often pools fade while compressing (`13` §12) |
| Real-time turn after combat | `ExitCombatMode` runs `HandleStrategicTurnImplicationsOfExitingCombatMode` (a real-time `HandleTacticalEndTurn`) at once unless a conversation is engaged | At the start of the next tactical tick (`TurnState.forceRealtimeTurn`), also inside a conversation; the boxing comparer runs it right after a probe that left combat | One tick later (`25` §3) |
| Miss animation in water | The splash tile has its own frame count from the tileset data | The ground miss timing (425 ms) everywhere | Rare; only shifts the barrier |
| Explosion timing | Tile-animation frames advance on the wall clock (strict `>`), no catch-up; frame counts from the STI aux data | Frame `k` at `k·(delay + 5)` game ms; frame counts from the STI aux data (graphic facts in the rule pack), `damageKeyframe + 1` without the graphic (stub pack) | Determinism (`12` §10.2) |
| Tile-animation pass | One list holds every tile animation; a damage key frame or a finished animation ends the pass for all later tiles, bullet misses and smoke graphics included | The early end stays within the explosion and water-ripple list; misses and smoke graphics are separate | Smoke graphics are cosmetic; misses live with the bullets |
| Water ripple | An armed object's ripple in water has `THIRDMISS1`'s tileset frame count; its key frame reads the freed physics slot | Ends one frame after its key frame 11, with its own owner and item | Only shifts later tile animations by one pass |
| Physics cadence and floats | `SimulateWorld` once per frame when the 20 ms counter is due; `sinf`, `sqrtf`, `hypotf` | Every 20 game ms on the tick grid; `Math.fround` of double `sin`/`sqrt` (correctly rounded), so a last-ulp `sinf` difference can rarely move a landing tile | Determinism (`34` §13) |
| World clock for smoke and light | Clouds and flares age by `GetWorldTotalSeconds`, which stops during turn-based combat | Campaigns (imports included) use the world clock; the sandbox counts `explosives.worldMs`, 5 ms per real-time tick (`stepExplosions`) | The sandbox has no strategic clock |
| Helicopter destruction | The third SAM hit plays the crash sound; `SkyriderDestroyed` runs from its end callback (the arrival event is deleted meanwhile) | `SkyriderDestroyed` runs at once | Game time (`25` §7.2) |
| Autoresolve slices | Slice length = wall time between frames × the speed (Play, Fast); only Finish runs fixed 1000 ms slices; retreat clicks land between frames | Always 1000 ms slices (Finish semantics); Pause/Play/Fast/Finish only pace the playback; retreats apply between slices | Outcomes independent of frame rate and clicks (`19` §2.6, §4.2, D1) |
| Endgame timing | Wall-clock timers of 2 s and 3 s, fades, the ending videos and credits, then `ReStartingGame` | Timers of 400 and 600 ticks; fades take no time; videos and credits are presentation; the session ends (`campaignWon`, flow `ended`, every command refused with `campaignOver`) instead of restarting | Determinism and the agent API (`26` §7.2) |
| Meanwhile wall-clock races | The capture message box and the interrogation's box race on wall-clock timers | The capture resolves first; the interrogation starts when its event and gates come | Determinism (`26` §9.2) |
| Remote trigger | The use-remote animation (standing) plays; the trigger acts at its frame | `useRemote` acts at once; the original's AP cost (2, plus 2 for the animation when standing) | No animation timing in the agent API |
| Waiting for mercs to exit | `guiWaitingForAllMercsToExitTimer`: 2500 ms of wall clock | 2500 game ms, checked after every soldier pass | Game time |
| Dialogue queue cadence | One queue event per game-screen frame; the trigger wait is 500 ms of `GetJA2Clock` | One event per tick after the tactical step; the trigger wait is 100 ticks of the tactical clock | Frame-rate independence (`24` §10.2) |
| A.I.M. annoyance | Hanging up early or waiting raises a merc's annoyance on the wall clock (`HandleMercAttitude`), which can lock him out until `EVENT_AIM_RESET_MERC_ANNOYANCE` (`Random(600)`) | Not simulated; the statuses and the reset event are kept for imports | No wall clock in the simulation (`21` §2.3) |

| Brothel time warp | The sex screen plays for about four seconds of wall time, then warps game time by `5 + Random(20)` minutes without event processing (`JAScreens.cc:478-483`) | The warp and its draw run at the NPC action and at the end of the brothel action item; `sexScene` is the presentation event | No screen; it draws nothing else (`29` §16) |
| San Mona screen and time | `SexScreenHandle` is not the game screen, so the tactical loop stops while the world clock runs (`UpdateClock` runs on every screen); then the clock jumps by `5 + Random(20)` minutes | The game page holds the real-time driver while the screen is up, as for a modal: no game time passes during its 4.2 s; the jump is the server's, at the action | One clock; the original's few seconds of strategic time are not visible (`30` §7.4) |
| Map screen pause during merc lines | A merc line queued on the map screen pauses the game (`LOCK_PAUSE_MERC_TALKING`) until the face finishes (`Dialogue_Control.cc:639-643`, `:425-429`) | Not paused: quotes are events, compression goes on | The simulation never waits for speech ("Speech") |
| Lost battle unload delay | `DeathNoMessageTimerCallback` unloads the sector 10 s of wall clock after a lost tactical battle (`Overhead.cc:4479`) | 10 s of tactical game time (`lostBattleUnloadAtMs`, `battle-flow.ts`) | Game time |
