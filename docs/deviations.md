# Deliberate deviations from the original

Every place where ja2-node knowingly behaves differently from JA2 Stracciatella with default settings (the behaviour
reference, `01` D1). Add an entry to the section it belongs to: the original's behaviour (with `file:line` where it
helps), what ja2-node does, and why. A gap still to close ends its *Why* with **Later.**

Most entries are permanent: they replace wall clocks, frames, sound lengths, message boxes, cursors and screens with game
time, commands and decision prompts, move cosmetic draws off the gameplay generator, keep saves free of side effects, or
avoid the original's undefined behaviour, hangs and softlocks.

## 2. Timing and clocks

Wall clocks, frames and sound lengths replaced by game time on 5 ms ticks (D3, `04` §3).

| Area | Original | ja2-node | Why |
|---|---|---|---|
| Timing | Wall-clock timers that never catch up; frame-rate dependent bullets, burst cadence and real-time AI slice | Fixed 5 ms ticks; bullets advance N tiles per tick; a fixed number of real-time AI soldiers per pass | Outcomes independent of FPS and CPU (`04` §3) |
| Speech | Quote duration is the audio length (speech on) or 60 ms per character, then 300 ms with the mouth closed | The longer of the two whatever a viewer's speech option: the sample length from the rule pack's voice lengths (`@rules/speech/lengths.json`, from the WAV headers at pack build) and 12 ticks per UTF-32 character of the decoded EDT line plus the first tick after it (the original tests `elapsed > duration`), then 60 ticks mouth closed; a quote never waits for the speaker's battle sound. The viewer that finished first (voice, or text with speech off) leaves only the 60 ticks through `skipLine {talkEnded}` (an input); a viewer with the other speech option trails by the difference | One simulation serves every viewer and must not depend on audio (`04` §3, §6.14, `24` §10.2) |
| Skipping every line | No such setting | `speech: skip` (`newSession`, `setSpeech`): every line ends on the tick after it is said, as if Backspace were pressed at once; its quote event carries `skipped` and no viewer shows it; a logged session setting, never saved | Agents playing with nobody listening (`04` §6.14) |
| Watchdogs | 15 s AI deadlock breaker, 25 s UI busy breaker | Not ported | A hang is a bug and must fail tests |
| Frame timers | `TIMECOUNTERDONE` against the wall clock, polled every 5 ms | Absolute game-ms deadlines checked on 5 ms ticks, same reset points | Same cadence without wall-clock jitter (`01` §3.5) |
| Enemy sighted on their turn | 3 s wall-clock pause (`GameScreen.cc`) | 3000 game ms; the simulation is not idle meanwhile, so time runs through our interrupt until it ends (`10` §6.9) | All timers run on game time |
| Bullet flight | `MoveBullet` is gated by a 2–3 ms wall clock and called once per frame, so flight time and burst overlap follow the frame rate | One tile per 5 ms tick at the start of the tick, the first inside `FireWeapon`; knives every 30 ms | Outcomes independent of FPS (`11` §3.3) |
| Game events | Fire events run in the frame's event pump | Same queue order, drained after each tick's soldier pass | No frame loop (`11` §1.2) |
| Our merc's death | The barrier is released after the portrait and skull animation (12 × 160 ms wall clock) | A fixed 1920 game ms after opcode 440 | UI timing has no game clock |
| Blood and smell decay period | `DecayBloodAndSmells` runs after more than 100 game seconds, or 5 real seconds of game time under compression (`5 · 300/1800/3600` s) | Always after more than 100 game seconds | Only changes how often pools fade while compressing (`13` §12) |

| Explosion timing | Tile-animation frames advance on the wall clock (strict `>`), no catch-up; frame counts from the STI aux data | Frame `k` at `k·(delay + 5)` game ms; frame counts from the STI aux data (graphic facts in the rule pack), `damageKeyframe + 1` without the graphic (stub pack) | Determinism (`12` §10.2) |
| Tile-animation pass | One list holds every tile animation; a damage key frame or a finished animation ends the pass for all later tiles, bullet misses and smoke graphics included | The early end stays within the explosion and water-ripple list; misses and smoke graphics are separate | Smoke graphics are cosmetic; misses live with the bullets |
| Water ripple | The ripple of an armed object in water has `THIRDMISS1`'s tileset frame count and its key frame reads the freed physics slot | Ends one frame after its key frame 11, with its own owner and item | Only shifts later tile animations by one pass |
| Physics cadence and floats | `SimulateWorld` once per frame when the 20 ms counter is due; `sinf`, `sqrtf`, `hypotf` | Every 20 game ms on the tick grid; `Math.fround` of double `sin`/`sqrt` (correctly rounded), so a last-ulp `sinf` difference can rarely move a landing tile | Determinism (`11` §7.13) |
| World clock for smoke and light | Clouds and flares age by `GetWorldTotalSeconds`, which stops during turn-based combat | Campaigns (imports included) use the world clock; the sandbox counts `explosives.worldMs`, 5 ms per real-time tick (`stepExplosions`) | The sandbox has no strategic clock |
| Helicopter destruction | The third SAM hit plays the crash sound and `SkyriderDestroyed` runs from its end callback (the arrival event is deleted meanwhile) | `SkyriderDestroyed` runs at once | All timers run on game time (`25` §12.2) |

| Brothel time warp | The sex screen plays for about four seconds of wall time, then warps game time by `5 + Random(20)` minutes without event processing (`JAScreens.cc:478-483`) | The warp and its draw run at the NPC action and at the end of the brothel action item; `sexScene` is the presentation event | No screen; it draws nothing else (`04` §6.28) |
