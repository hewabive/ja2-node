# Deliberate deviations from the original

Every place where ja2-node knowingly behaves differently from JA2 Stracciatella (the behaviour reference, see
`01-architecture.md` D1). Add an entry whenever a port departs from the source, in the section it belongs to, with the
original's behaviour (and its `file:line` where it helps), what ja2-node does, and why.

Most entries are meant to stay: they replace wall clocks, frames, sound lengths, message boxes, cursors and screens with
game time, commands and decision prompts, move cosmetic draws off the gameplay generator, keep saves free of side
effects, or avoid the original's undefined behaviour, hangs and softlocks. An entry that records a gap still to close
ends its *Why* with **Later.** (planned, no milestone yet) or **M8.** (comes with the player UI and its renderer, `01`
§10). The list was checked against the code for the M7 release (2026-10-18): closed gaps were removed, and the
milestone tags of the earlier slices were replaced by these two.

## 2. Timing and clocks

Wall clocks, frames and sound lengths replaced by game time on 5 ms ticks (D3, `04` §3).

| Area | Original | ja2-node | Why |
|---|---|---|---|
| Timing | Wall-clock timers that never catch up; frame-rate dependent bullets, burst cadence and real-time AI slice | Fixed 5 ms ticks; bullets advance N tiles per tick; a fixed number of real-time AI soldiers per pass | Outcomes independent of FPS and CPU (`04` §3) |
| Speech | Quote duration is the audio length (speech on) or 60 ms per character | Always 60 ms per character in the simulation: 12 ticks per UTF-32 character of the decoded EDT line, the face finishes on the first tick after that (the original tests `elapsed > duration`); a quote never waits for the speaker's battle sound | The simulation must not depend on audio (`04` §3, `24` §10.2) |
| Watchdogs | 15 s AI deadlock breaker, 25 s UI busy breaker | Not ported | A hang is a bug and must fail tests |
| Frame timers | `TIMECOUNTERDONE` against the wall clock, polled every 5 ms | Absolute game-ms deadlines checked on 5 ms ticks, same reset points | Same frame cadence without wall-clock jitter (`03` §7) |
| Enemy sighted on their turn | 3 s wall-clock pause (`GameScreen.cc`) | 3000 ms of game time | All timers run on game time |
| Bullet flight | `MoveBullet` is gated by a 2–3 ms wall clock and called once per frame, so flight time and burst overlap follow the frame rate | One tile per 5 ms tick at the start of the tick, the first tile inside `FireWeapon`; knives every 30 ms | Outcomes independent of FPS (`11` §3.3) |
| Game events | Fire events run in the frame's event pump | Same queue order, drained after each tick's soldier pass | Same order without a frame loop (`11` §1.2) |
| Our merc's death | The barrier is released after the portrait and skull UI animation (12 × 160 ms wall clock) | A fixed 1920 game ms after opcode 440 | UI timing has no game clock |
| Blood and smell decay period | `DecayBloodAndSmells` decays blood and smells when more than 100 game seconds passed, or 5 real seconds of game time under time compression (`5 · 300/1800/3600` s) | Always after more than 100 game seconds | Only changes how often pools and trails fade while compressing (`13` §14) |
| Real-time turn after combat | `ExitCombatMode` runs `HandleStrategicTurnImplicationsOfExitingCombatMode` (a real-time `HandleTacticalEndTurn`) at once unless a conversation is engaged | The forced real-time turn runs at the start of the next tactical tick (`TurnState.forceRealtimeTurn`), also inside a conversation; the boxing oracle comparer runs it right after a probe that left combat | One tick later; found with the boxing oracle (`25` §7) |
| Miss animation in water | The splash tile has its own frame count from the tileset data | The ground miss timing (425 ms) is used everywhere | Rare; the release time only shifts the barrier |
| Explosion timing | Tile-animation frames advance on the wall clock (strict `>`), no catch-up; frame counts from the STI aux data | Frame `k` at `k·(delay + 5)` game ms on 5 ms ticks; frame counts read from the STI aux data (stored as graphic facts in the rule pack, `28` §17.4), `damageKeyframe + 1` when the graphic is missing (stub pack) | Determinism (`12` §10.2) |
| Tile-animation pass | One list holds every tile animation; a damage key frame or a finished animation ends the pass for all later tiles, including bullet misses and smoke graphics | The early end is kept within the explosion and water-ripple list; miss animations and smoke graphics are separate | Smoke graphics are cosmetic; misses live with the bullets |
| Water ripple | The ripple of an armed object in water has the tileset frame count of `THIRDMISS1` and its key frame reads the freed physics slot | The ripple ends one frame after its key frame 11 and keeps its own owner and item | The ripple length only shifts later tile animations by one pass |
| Physics cadence and floats | `SimulateWorld` runs once per frame when the 20 ms counter is due; `sinf`, `sqrtf`, `hypotf` | Every 20 game ms on the 5 ms tick grid; `Math.fround` of double `sin`/`sqrt` (correctly rounded), so a last-ulp difference of `sinf` can rarely move a landing tile | Determinism (`11` §7.13) |
| World clock for smoke and light | Clouds and flares age by `GetWorldTotalSeconds`, which stops during turn-based combat | Campaigns, imported saves included, use the world clock; the sandbox counts `explosives.worldMs`, advanced 5 ms per real-time tick by `stepExplosions` | The sandbox has no strategic clock |
| Helicopter destruction | The third SAM hit plays the crash sound and `SkyriderDestroyed` runs from its end callback (the arrival event is deleted meanwhile) | `SkyriderDestroyed` runs at once | All timers run on game time (`25` §12.2) |
| Autoresolve slices | Slice length is the wall time between frames times the speed (Play, Fast); only Finish runs fixed 1000 ms slices; retreat clicks land between frames | Always 1000 ms slices (Finish semantics); Pause/Play/Fast/Finish only pace the playback; retreat orders apply between slices | Outcomes independent of frame rate and click timing (`19` §2.6, §4.2, D1) |
| Endgame timing | Wall-clock timers of 2 s and 3 s, fades, the ending videos and credits, then `ReStartingGame` | Timers are 400 and 600 ticks; fades take no time; videos and credits are presentation; the end comments come from every conscious non-EPC merc placed in the loaded sector; the session ends (`campaignWon`, flow `ended`, every command refused with `campaignOver`) instead of restarting | Determinism and the agent API (`26` §7.2) |
| Meanwhile wall-clock races | The capture message box and the interrogation's box race on wall-clock timers | The capture resolves first, then the interrogation starts when its event and gates come | Determinism (`26` §10.2) |
| Remote trigger | Pressing the remote trigger plays the use-remote animation (standing) and acts at its frame | `useRemote` acts at once; the AP cost is the original's (2, plus 2 for the animation when standing) | No animation timing in the agent API |
| Waiting for mercs to exit | `guiWaitingForAllMercsToExitTimer` gives the walk-off 2500 ms of wall clock | 2500 game ms, checked after every soldier pass | All timers run on game time |
| Dialogue queue cadence | One queue event per game-screen frame; the trigger wait is 500 ms of `GetJA2Clock` | One event per 5 ms tick after the tactical step; the trigger wait is 100 ticks of the tactical clock | Frame-rate independence (`24` §10.2) |
| A.I.M. annoyance | Hanging up early or waiting raises a merc's annoyance on the wall clock (`HandleMercAttitude`), which can lock him out until `EVENT_AIM_RESET_MERC_ANNOYANCE` (`Random(600)`) | Not simulated: no wall-clock impatience; the statuses and the reset event are kept for imports | No wall clock in the simulation (`21` §2.3) |
| Carmen's departure timer | `CarmenLeavesSectorCallback` runs on a 10 000 ms customizable timer of the wall clock, not saved | Runs after 10 000 ms of tactical game time; the deadline is session state (`state.talk.carmenTimerAtMs`) and is saved with the session | All timers on game time (`25` §12.2); exact reloads (`27` §1.3) |
| Brothel time warp | The sex screen plays for about four seconds of wall time and then warps game time by `(5 + Random(20))` minutes without event processing (`JAScreens.cc:478-483`) | The warp and its draw run at the NPC action and at the end of the brothel action item; `sexScene` is the presentation event | There is no screen; the screen does nothing else that draws (`28` §12.5 finding 1) |
