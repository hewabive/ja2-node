# Bugs of the original that ja2-node does not reproduce

Every place where the original's own outcome is a bug and ja2-node knowingly does something else. An entry gives the
original's behaviour in one clause with a `file:line` in `reference/stracciatella`, what ja2-node does, and why. Other
docs cite entries by their *Area* name (`original-bugs "Area"`); names are unique across this file and
`deviations.md`.

What goes where:

- A bug the original's players meet is behaviour too: ja2-node keeps it by default (`01` D1) and pins it as a quirk,
  with its test, in the subsystem's doc.
- §1: the original crashes, hangs, softlocks, waits for a watchdog or reads past its data, so it has no behaviour to
  keep. ja2-node always defines one, the smallest step from the original it can find.
- §2: a defined outcome that is plainly unintended, fixed by the maintainer's decision, because a design rule rules it
  out (`01` D7, D15, D16), or by the rare-bug rule (§2); the Why column names which.
- A bug that Stracciatella itself brought into v0.22.1, absent from vanilla, is not reproduced (`01` D1). Its entry
  goes in §1 or §2, and its Why says "Stracciatella regression".
- `deviations.md`: ja2-node reaches the original's outcome another way (game time, commands and prompts, saves without
  side effects, generator streams, presentation in the client) or leaves out something that is not gameplay.

Original links are under `reference/stracciatella/src/game/`, or under `reference/stracciatella/` when they start with
`src/` or `rust/`; `M:` is Stracciatella master `ae6bf01`, for code v0.22.1 lacks (`01` §3.10).

### 1.2. Busy states only a watchdog ends

UI busy breaker ends. ja2-node has no watchdog (deviations "Watchdogs"): a stuck state would keep `advance` from going
idle and the turn from ending, so each case ends where the original meant it to.

## 2. Gameplay bugs fixed on purpose

Each needs the maintainer's decision, a design rule that rules the bug out, or the rare-bug rule. Every other bug of the
original stays (`01` D1).

The rare-bug rule fixes a bug that meets all of these:

- it is plainly unintended;
- it needs conditions real play rarely meets, and players do not use it on purpose;
- reproducing it takes state, branches or plumbing that exist only for the bug, so the fix is the smaller code (a bug
  that falls out of the ported code for free stays);
- the fix leaves every random draw outside the bug's own case, and their order, as they were, and changes no oracle
  probe's comparison;
- the results of the bug that a native save already holds still load as they are.

A case that meets the rule only arguably goes to the maintainer.

A fix that a later Stracciatella (master, v0.23 on) makes is no reason by itself: the bug stays (maintainer's rule,
2026-11-20). The maintainer takes such a fix only in two cases:
- the bug is plainly unintended, and the fix changes no outcome of normal play (what can happen, its odds, its costs);
- the bug is an exploit, such as duplicating money. When only the agent API reaches the exploit, the API refuses what
  the original's UI cannot do, and the rule stays as it is.

Suppression immunity is an example that does not qualify. The original never resets `ubAPsLostToSuppression`, so
suppression costs a merc APs about once. Master's reset changes every firefight, so the bug stays (`33` §3).
