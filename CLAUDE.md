# CLAUDE.md

ja2-node is a non-commercial TypeScript reimplementation of Jagged Alliance 2. The goal is the
original's behaviour (formulas, constants, check order, integer truncation, PreRandom semantics),
not a line-by-line port; the behaviour reference is JA2 Stracciatella with default settings.
The simulation is server-side (Node), the browser is a client, agents play through an API.

## Rules

- Keep this file compact: add only what cannot be learned quickly from the code or `docs/`.
- No comments in code. Make code self-explanatory through names, small functions and named
  constants. The only exception is the SFI-SCLA header below.
- Everything in the repository is English (code, docs, commit messages). Talk to the maintainer
  in Russian.
- Never commit original game data or anything derived from it (extracted files, JSON produced
  from `Ja2bin.dat`, screenshots). The data lives outside the repo, in `$JA2_DATA_DIR`.
- Stub content is CC0 1.0 (`stubs/NOTICE.txt`): keep it own work; a stub file built from Stracciatella's tables goes
  on the notice's SFI-SCLA list (`docs/27` §6.2).
- `reference/` holds third-party sources: read-only, gitignored. Never copy code from
  `reference/ja2-web` (GPL claim).

## Commands

- `pnpm check`: Biome, `tsc -b`, layer imports, unit tests. Run before calling a change done.
- `pnpm e2e`: Playwright against the stub pack.
- `pnpm gates`: the gates the changed files can affect (`--list` shows the plan, `--all` runs every one).
  `pnpm test:data` (with `JA2_DATA_DIR`) and `pnpm test:reload` run only the unit tests those modes change.
- `pnpm dev`: server (7420) + Vite (5173). Add `JA2_DATA_DIR="…/Data"` for the original data.
- `pnpm stubs`, `pnpm cli inspect …` (`pnpm cli --help`), `pnpm cli bench <scenario|all>` (`docs/27` §7).

## Conventions

- Node runs `.ts` directly: no `enum`, `namespace` or constructor parameter properties; relative
  imports end in `.ts`; type-only imports use `import type`.
- Layer boundaries: tsconfig project references + `tools/check-imports.ts`. `core`, `content` and
  `sim` are DOM-free, Node-free and deterministic: no `Math.random`, `Date`, timers.
- Fixed-width integer fields of the original go through `src/core/int.ts` (`u8`, `i16`, `idiv`…).
- Constants of the original keep their literal values (`PI` is `3.1415926` as in `sgp/Types.h`, never `Math.PI`), so
  Biome's `noApproximativeNumericConstant` is off. Any other Biome warning fails `pnpm lint`.
- Files derived from original or Stracciatella logic start with:
  ```ts
  // Derived from Jagged Alliance 2 source code (Strategy First SFI-SCLA) via JA2 Stracciatella.
  // Modified for ja2-node: reimplemented in TypeScript, <YYYY-MM-DD>. See LICENSE (SFI-SCLA).
  // @src <path in Stracciatella>
  ```
- Tables transcribed from Stracciatella sources live in `data/tables/` and are generated by
  `tools/transcribe/*.ts`; regenerate instead of editing by hand.
- Tests live next to the code (`*.test.ts`). Tests that need original data use
  `describe.skipIf(!ORIGINAL_DATA_DIR)` (`tests/support/original-data.ts`); CI runs on stubs only.
  Unit tests read the stub pack built once per run (`sharedStubPackDir()`, read-only).

## Docs

Docs describe the current product; history stays in git. Code does not cite doc sections (numbers move); docs cite
code paths and `file:line` in `reference/stracciatella`.

- `docs/01-architecture.md`: licensing, decisions D1–D16, layers, sim-core rules (time, RNG streams, state),
  Stracciatella vs vanilla, documentation map.
- `docs/04-time-and-server.md`: tick model, time drivers, server and sessions, rule pack, the agent API (§6, by topic).
- `docs/05`–`09`: render pipeline, soldiers and animation, structures/pathing/walking, sight and noise, green AI.
- `docs/10`–`14`: turn-based, attacks, items and explosions, combat AI, savegames (import in §10).
- `docs/15`–`19`: strategic time, map and movement, strategic AI, towns and assignments, PBI and autoresolve.
- `docs/20`: tactical lighting (light sprites, true light level).
- `docs/21`–`23`: laptop and hiring, contracts and relationships, merchants.
- `docs/24`–`26`: NPCs and dialogue, quests/facts/NPC actions/schedules, meanwhiles and the ending.
- `docs/27-platform.md`: saves, options, sound and music, video, localization, stubs, performance.
- `docs/28-player-ui.md`: the `ui` layer, widgets, layouts as data, fonts, the original screens, client-side hints.
- `docs/deviations.md`: every deliberate difference from the original; add to it when diverging.
- `docs/releases.md`: release notes.
- `tools/oracle/README.md`: the native oracle (probe build, probes, comparers).
